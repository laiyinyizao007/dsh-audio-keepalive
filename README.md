# dsh-audio-keepalive

让 Harness 网页端在**手机不锁屏、但页面切到后台**时依然能播报。

## 为什么需要它

`dsh-tts` 的 `speakReplies` 可以在任务完成时念出结果，这是最省事的"任务结束提醒"。
但手机上有个硬限制：**iOS 会挂起后台标签页**，于是"完成"事件根本收不到，更别说出声。

iOS 有个例外：**页面持有活跃音频会话时，后台页面不会被冻结** —— 定时器、socket 都还活着。
所以这个插件做一件很小的事：放一段**音量 0 的静音循环**，把音频会话占住。

两个关键细节：

- 元素**不能是 `muted`**。iOS 上 muted 的元素不持有会话；`volume = 0` 持有，且听不见。
- 会话只能由**用户手势**打开。插件等第一次点击/触摸/按键后才启动。

会话被系统收走时（来电、拔耳机、iOS 回收媒体会话）会自动重新拉起：每 5 秒检查一次，
页面重新可见时也检查一次，用户再次手势时也检查。

## 效果

右下角有一个小药丸：

| 状态 | 含义 |
| --- | --- |
| 🔈 点此开启播报保活 | 还没点过页面，等一次手势 |
| 🔈 点此允许播报 | 浏览器拒绝了播放，需要再点一下 |
| 🔊 播报保活中 | 会话已持有，页面在后台也能出声 |
| 🔇 播报保活已关 | 你手动关掉了 |

点它可以开关保活。

## 安装

```bash
cd ~/.dsh/profiles/web
pnpm add link:/home/averypi/dsh-audio-keepalive
```

并把 `dsh-audio-keepalive` 加进 `package.json` 的 `dsh.profile.bundles`。

## 使用

1. 手机浏览器打开 Harness，**点一下页面**（解锁音频会话）。
   - 播报本身不需要 HTTPS：`http://` 的地址也能放音。
   - 但**麦克风**（浏览器内语音输入）需要 HTTPS 或 localhost，那是另一条路。
2. 之后切到别的 app、屏幕保持点亮 → 任务完成时网页会念出来。

锁屏则不保证：iOS 可能在锁屏后回收静音声频会话并冻结页面。此时靠 Telegram 推送兜底。

## 测试

```bash
npm install --include=dev
npm test
```

行为测试：手势前不开会话、元素在播且静音、会话丢失后自动恢复、关闭后页面复原、
生成的 WAV 确实是静音。
